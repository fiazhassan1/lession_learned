# Project task and resource discipline

Source: Fiaz's 7–8 October decisions in GBOB #49, chatbot #4 and Lessons #9. Applies to authorized task execution without changing project roles or business scope.

- Before costly work, write a bounded task card: phase, outcome, acceptance criteria, developer, independent reviewer, approved scope/exclusions, affected interfaces, tests, risks and checkpoint budget. Configure business counts/limits and avoid copying domain examples.
- Verify the current repository, branch, exact head, dirty state, actual implemented behavior and known defects. Never declare a stale check current or discard uncommitted work.
- Keep one coherent change and run the relevant checks. Developer QA, independent QA, CI and UI/business acceptance are distinct.
- Record tokens, cost, elapsed active time and retries only when measured; otherwise write unavailable. Do not invent usage or promise work between sessions.
- At checkpoint/resume, retain task card, exact-head check record, evidence links, usage ledger and handoff with next action/owner.
- Stable policy belongs in agent instructions; volatile progress belongs in issues/status records. Preserve files, safety gates and reviewer independence.
- The portable source remains in the linked adoption issues; project skill installation is a separately tracked pending gate. Runtime availability is a separate verification gate; file installation alone is not proof an agent loaded or executed it.
